# 排障与回滚

## 按返回结果定位

| 现象 | 优先检查 |
| --- | --- |
| 入口返回 404 | 入口代理前缀、HTTPRoute、网关 Path 和服务 context-path 是否拼接正确 |
| 业务请求返回 401 | 请求是否进入正确路径、Bearer token 是否有效、是否走了适用的认证流程 |
| 返回 403 | 服务端资源权限与功能开关，不通过扩大网关匿名白名单解决 |
| 返回 503 | Nacos namespace/发现分组、服务注册名、健康实例与网络连接 |
| Nacos 配置发布后仍使用旧路由 | 检查每个网关实例是否接受新配置；无效配置会被拒绝并保留旧快照 |
| Pod ImagePullBackOff | 镜像地址、Registry Secret、节点 DNS、网络和证书 |
| Argo CD 读取 GitHub 失败 | repo-server 的 DNS、连通性及仓库凭据；不要仅凭本地清单缓存判定 Git 已恢复 |
| Argo CD 显示 OutOfSync | 先检查实际字段差异，区分资源跟踪注解与服务模板、镜像或环境变更 |

## 网关启动失败

动态路由启用时，初始 Nacos 配置缺失或无法编译会阻止启动。先确认 namespace ID、Group、Data ID 和凭据，再检查 YAML 与路由 ID。不要通过关闭鉴权或删除公共路由来绕过错误。

正常运行后的错误更新会保留上一份进程内有效配置。需要清空业务路由时明确发布 `routes: []`，不要删除整个配置。

## 回滚路由与镜像

- 仅路由错误：在 Nacos 配置历史恢复上一个有效版本并发布，确认所有实例加载。
- 网关二进制错误：在部署 Git 中恢复已验证镜像版本，经 Argo CD 同步后观察新 Pod。
- 账号服务、数据库结构和密码编码变化：按对应项目迁移文档执行，不能仅把网关镜像回滚视作全链路回滚。

保留可追溯的 Git 提交和 Registry 摘要。清理构建缓存或旧镜像前，先确认不影响当前发布与回滚所需版本。
